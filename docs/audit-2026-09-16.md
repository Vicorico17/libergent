# LiberGent code audit — 2026-09-16

Read-only audit of commit `81c8e23` (main, 2026-09-15). Nothing in this batch changes runtime code; it records what was found so the fixes can be scheduled against the existing P0–P3 backlog in [premium-alerts-todo.md](premium-alerts-todo.md).

## Method and limits

- Baseline verified on a clean clone: `npm test` 172/172 pass, `npm --prefix ui run lint:ci` clean, `tsc --noEmit` in `ui/` clean, worktree clean.
- Nine read-only agents each mapped one subsystem (full maps in [audit-2026-09-16/](audit-2026-09-16/)); a tenth re-derived the status of every TODO item in `docs/` from the code ([todo-reconciliation.md](audit-2026-09-16/todo-reconciliation.md), 210 items).
- Items in **Section 1** were reproduced by hand with offline `node` runs against the modules or by reading the exact lines. Items in **Section 2** come from the agent maps and were **not** independently re-run; treat them as leads.
- No production endpoint, marketplace, Supabase project or browser provider was contacted. Live-markup compatibility of the parsers is therefore unverified.
- The planned adversarial-verification and gap-finding stages did not complete (session limits), so this is an inventory, not a complete audit.

## 1. Verified defects (reproduced)

Ordered by impact on the owner-confirmed tech-first direction.

### 1.1 Tech queries containing a vehicle-make word are classified as vehicles — critical

- `src/query-understanding.js:16-23` (`VEHICLE_MAKES` contains `mini`, `smart`, `ds`, `mg`, `seat`) and `:107-112` (`findVehicleMake` matches any whole word).
- Reproduced: `understandMarketplaceQuery()` returns `category: "vehicle"`, confidence 0.9, for `iphone 13 mini`, `ipad mini`, `mac mini m2`, `smart tv samsung`, `nintendo ds`.
- Downstream: `src/relevance.js:940-947` adds the `vehicle` category, `:1462-1467` applies the 7000 RON vehicle price floor, so a real `Apple iPhone 13 mini 128GB` at 1800 RON is returned as `listingType: spare_part`, `isRecommendedCandidate: false`, rejections `type_mismatch`, `irrelevant:price_below_category_floor`. Every such search returns zero products. `src/sites.js:271-273` also routes these queries to vehicle sources.
- Fix direction: require a second vehicle signal (model, year, engine, `km`) for ambiguous makes, or exclude short ambiguous makes when a phone/tech family pattern also matches.

### 1.2 `isCarQuery` matches keywords as substrings — high

- `src/sites.js:245-279`: `CAR_KEYWORDS` are tested with `joined.includes(keyword)` on the joined token string; a year plus variant-code rule also fires on tech model codes.
- Reproduced `true` for `chitara electrica`, `combina frigorifica`, `aspirator automat`, `parfum diesel`, `samsung galaxy s24 2024`. Car routing (`src/sites.js:1213-1222`) then drops Vinted/Price.ro/ShopMania and adds Autovit/BestAuto for these queries.
- Fix direction: token-boundary matching and a minimum of two independent vehicle signals.

### 1.3 Generic "part" tokens and category exclusions reject complete products — high

- `src/relevance.js:43-81` (`NEGATIVE_INTENTS.part` contains `usa`, `display`, `baterie`, `acumulator`, `motor`, `cap`, `placa`, `modul`, `suport`), `:621-635` (`CATEGORY_EXCLUSIONS.phone` contains `sim`; `.console` contains `controller`, `jocuri`, `joc`), `:1303-1320` (`getListingType` refuses `main_product` on any `part`/`irrelevant` match and falls through to `spare_part`).
- Reproduced, all with `isRecommendedCandidate: false`: `iPhone 15 Pro 128GB adus din USA` (`part:usa`), `iPhone 15 128GB dual sim` (`irrelevant:sim`), `Consola Sony PS5 cu controller` (`irrelevant:controller`), `iPhone 13 128GB baterie noua` (`part:baterie`).
- Dual-SIM phones and console bundles are the dominant listing shapes for these categories; the existing `BUNDLE_MARKERS` carve-out (`:357-363`) does not cover them.

### 1.4 Generic retail parser throws on JSON-LD `offers: []` — high

- `src/parsers/retail.js:72`: `Array.isArray(product.offers) ? product.offers[0] : ...` yields `undefined`, then `offer.url`/`offer.lowPrice` throws `TypeError`. The `.map` at `:99` is not guarded, so `parseRetailHtml` fails the whole source.
- Reproduced with a one-product page: `TypeError: Cannot read properties of undefined (reading 'url')`. Affects every `direct-html-retail` adapter (15+ sites) whose page embeds an empty offers array.

### 1.5 Vehicle price history is never written — high

- `src/supabase.js:357`: rows are filtered with `Number(listing.price ?? listing.priceRon ?? listing.numericPrice)`. `normalizeListing` (`src/normalize.js:159`) always sets `price` to the text label (`"27 500 EUR"`), so `Number()` is `NaN` for every priced listing.
- Reproduced with a mocked fetch: returns `false`, zero rows posted. `/api/vehicle/price-history` (`src/worker.js:1298`) and days-on-market can never populate. Fix: test `priceRon ?? numericPrice` first.

### 1.6 Condition filter drops listings with empty condition and accepts "Ca nou" as new — high

- `src/aggregate.js:79` (`matchesCondition`): `used` requires `utilizat|folosit|second`, `new` accepts any substring `nou`.
- Reproduced: `condition=used` with listing condition `""` returns 0 items; `condition=new` with `Ca nou` returns 1 item. Publi24 always emits `""` (`src/parsers/publi24.js:77`); OLX only when a badge exists; Flip/Klap emit grade words. Whole sources vanish when the user picks a condition. No test covers `condition != 'any'`.

### 1.7 Autovit JSON-LD price backfill uses the wrong index — medium

- `src/parsers/autovit.js:172-188`: prices are back-filled with `jsonLdOffers[index]` where `index` is the position after filtered blocks are removed, but JSON-LD follows unfiltered page order.
- Reproduced: first `<article>` is a category link (dropped), the second listing receives the first JSON-LD price (1000 EUR instead of 2000 EUR).

### 1.8 OLX `hasNextPage` is true on the last page — medium

- `src/parsers/olx.js:166`: any `page=N` href sets `hasNextPage`, including the "previous" link. Reproduced with a page containing only `?page=1` → `true`. Same unanchored pattern in `vinted.js:79-81`, `anuntul.js:139-141`, `publi24.js:97-99`, `okazii.js:160-162`. `src/search.js:385-403` then fetches extra pages when `totalResults` is null.

### 1.9 Seller phone lookup is unauthenticated and can start paid browser sessions — high (security/cost)

- `src/worker.js:1359-1401` has no auth check before `resolveListingPhones` (`:708`) → `revealOlxPhonesWithBrowser` (`src/providers/cloudflare-browser.js:28`, Chromium, ~45 s worst case per URL). The 15-minute cache (`:32`) is per listing URL, so iterating URLs bypasses it. README:30 describes seller contact as an authenticated feature; the UI only calls it after checking the session (`ui/src/app/search/page.tsx:1520-1526`), so adding the same Bearer check server-side is low risk.

### 1.10 Admin token accepted in the query string and compared with `===` — medium (security)

- `src/worker.js:266-272`, `src/server.js:54-60`: `?token=` is accepted (leaks into logs/analytics/referrers) and compared with plain equality. `scripts/benchmark-kitesurf.js:83` already uses the header only. Fix: drop the query-string carrier, use a constant-time compare.

### 1.11 `/api/whatsapp/send` has no rate limit or per-user quota — high (abuse)

- `src/worker.js:1217-1296`: any authenticated account can send free text up to 2000 chars to any Romanian mobile number; no quota, opt-in template, opt-out handling or consent record. The consent gates in `src/outreach.js` / `src/call-pipeline.js` are not on this path. Risk: WhatsApp number ban.

### 1.12 Supabase tables without RLS and a callable SECURITY DEFINER function — high (security, live project not checked)

- `supabase/search_tracking.sql:194-201` enables RLS only for `email_leads`, `offer_feedback`, `saved_searches`, `user_entitlements`, `alert_*`. `search_events`, `search_query_stats`, `keyword_stats`, `vehicle_price_observations` have neither RLS nor a `revoke ... from anon, authenticated` (compare `:332-341`).
- `public.log_search_event` (`:253-268`) is `security definer`; `:347` grants execute to `service_role` but never revokes the Postgres default `EXECUTE ... TO PUBLIC`. With the publishable key shipped in the UI bundle, anyone could call the RPC and inflate the public trends page.
- Verify against the live project before acting; if confirmed, add RLS + revokes and `revoke execute on function public.log_search_event from public, anon, authenticated`.

### 1.13 Undocumented global Premium bypass flag — medium

- `src/supabase.js:406`: `LIBERGENT_PREMIUM_ALERTS_BETA === '1'` marks every authenticated user Premium before the entitlement lookup. Not in README or `.env.example`, no test.

### 1.14 Search page restarts the search when the account plan resolves — medium (UX/cost)

- `ui/src/app/search/page.tsx:3030`: the search effect depends on `accountPlan` and `account.userId`; `accountPlan` transitions `checking → free/premium` after the session and `/api/alerts` probe resolve, so the first Free search is aborted and re-issued (twice for signed-in users), resetting the loader.

### 1.15 "Live" labels contradict a checked TODO item — low (docs/product)

- `premium-alerts-todo.md` marks "label collection time instead of live" as done, but `ui/src/app/search/page.tsx:188`, `:880` (`Live Search`), `:3164`, `:3188` (`Recommendation updated live`), `:3420` (`Updated Live`) still render live wording.

### 1.16 Landing page lists experimental sources and omits active ones — low (marketing)

- `ui/src/components/sections/Platforms.tsx:1-11` lists Anunțul, Price.ro and ShopMania (demoted to experimental on 2026-09-15) and omits BestAuto, Flip and Klap (active). Contradicts `marketplace-integration-todo.md` UI rule "only list a source as searched when it is active".

### Probed but not confirmed

- Okazii "last amount wins" (`src/parsers/okazii.js:112`): a synthetic card did not parse at all in the probe, so the claim is unverified.
- Viewer cache-key collision for unrecognized cities (`src/location-intelligence.js:119`): the probe with named unknown cities produced distinct keys; the reported `Zona ta` path (no city at all) was not exercised.

## 3. Test coverage gaps (from the maps)

- No real-page HTML fixtures anywhere; all 18 parser tests use hand-written snippets. Zero tests for `parseAutovitHtml`, `parseVintedHtml`, `parseEvomagHtml`, the `parseSiteHtml` dispatcher, and every `hasNextPage`/`totalResults` helper except Anuntul's.
- `src/aggregate.js`: no test for `condition != 'any'`, `parsePostedAtDate` branches, used-listing dedupe, `ok:false` inputs, most `buildRiskFlags` codes.
- `src/relevance.js`: no tests for wanted/service/broken intents, bundles, dual-SIM/controller/USA/display false positives (which is why 1.3 went unnoticed).
- `src/server.js`, `src/health.js`, `src/env.js`, the Worker `scheduled()` handler and the whole alert delivery pipeline, all admin routes, `/api/image`, `/api/leads`, `/api/saved-searches`, `/api/history`: no tests.
- `ui/` has no test runner at all.
