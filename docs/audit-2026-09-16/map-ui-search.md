# Subsystem map: Next.js search experience (ui/src/app/search/**, ui/src/components/search/**, ui/src/components/SearchBar.tsx)

Generated 2026-09-16 by a read-only code-reading agent. Evidence is `path:line` on commit 81c8e23. Claims were not independently re-verified unless noted in the [summary](../audit-2026-09-16.md).

## Summary

The search experience is a single 3647-line client component file, ui/src/app/search/page.tsx, exported as a static Next.js route (`output: "export"`, ui/next.config.ts:9) and wrapped in Suspense so `useSearchParams` works (page.tsx:3641-3646). All routing state lives in the URL: `q`, `tier` (free|premium) and `near` (page.tsx:2651-2653). On mount, `SearchResultsContent` resolves the Supabase session via `useAccountSession`, then probes Premium entitlement by calling GET /api/alerts and interpreting 200 vs 403 `premium_required` (page.tsx:2698-2722). It derives `effectiveSearchTier` (premium only when the URL asks for it AND the probe says premium) and issues one fetch to /api/search/free or /api/search/premium with `site=all&provider=auto&limit=180&pages=2[&near=]`, adding a Bearer token for Premium (page.tsx:2921-2943). The raw `SearchPayload` is normalized in ui/src/app/search/search-data.ts: `mapSearchResults` drops failed sources and round-robin interleaves per-site items (search-data.ts:362-370, 795-806); `mapListing` normalizes price (priceRon > numericPrice > parsed text, EUR estimated at x5), source kind (used vs new by sourceType), condition, posted date, images (OLX CDN rewritten to /api/image proxy), and every scoring sub-object (dealQuality, evidenceConfidence, recommendation, riskFlags, priceInsight, phoneSpecs, proximity, keywordSignals) with defaults (search-data.ts:398-594). Summary fields consumed are bestUsedOffer, closestUsedOffer, bestNewBenchmark (resolved back to mapped items by URL/title via `mapOffer`), viewerLocation, duplicateListings, priceIntelligence, queryUnderstanding, searchedAt, totalListings/parsedListings/matchedListings/queryMismatchListings/excludedListings, marketplaces/successfulMarketplaces/blockedMarketplaces, plus per-result ok/provider/itemCount/error for the coverage grid (page.tsx:2955-2988). Filters (sort, sources, sourceTypes, conditions, priceMin/Max) are React state seeded from and mirrored to localStorage key `libergent-search-filters-v3` (page.tsx:470-509, 2856-2866) and applied client-side in `filteredResults`, together with session-only feedback exclusions (page.tsx:3092-3113). The page then splits results into a RecommendationCard (label "Best Used Deal" only when `recommendation.strong`, page.tsx:1949), optional ClosestDealCard (needs viewerLocation) and BenchmarkCard (cheapest new-source item, page.tsx:3120-3129), a paginated "Second-hand deals" grid and a "New price benchmarks" grid of ResultCards (page.tsx:3542-3609), and a collapsed "Search Report" diagnostics panel (page.tsx:3391-3494). Authenticated-only features are favorites (localStorage per user id via ui/src/lib/account-data.ts), structured like/dislike feedback POSTed to /api/feedback with local hide-and-rerank (page.tsx:2734-2805), WhatsApp seller outreach via /api/marketplace/contact + /api/whatsapp/send (page.tsx:1513-1599), and a ConversationCenter polling /api/conversations (page.tsx:2503-2635). A ListingDetailDrawer lazily fetches /api/marketplace/details and, for vehicle-looking queries, /api/vehicle/price-history (page.tsx:2215-2245). Vehicle-specific UI (CarBuyerJourney, VehicleTrustChecklist, DealerEvidenceSnapshot, VehicleCompareTray) is gated by a client keyword heuristic `isLikelyVehicleSearch`, not by the API's queryUnderstanding.category (page.tsx:160-171). The loading overlay is fully simulated: progress follows a timer curve to 97% and per-source bars use hardcoded start/end percentages (page.tsx:77-110, 2910-2919). ui/src/components/search/ProductCard.tsx and SearchFilters.tsx are not imported anywhere (legacy dead code); ui/src/components/SearchBar.tsx is used only by ui/src/app/trends/TrendsClient.tsx. The file SearchClient.tsx named in the task (and in docs/lib-14-website-capability-matrix.md:21) does not exist.

## Notable design decisions

- Everything is one 'use client' file with ~20 useState hooks in SearchResultsContent (page.tsx:2655-2696); no reducer, no context, no separate component files
- Static export + useSearchParams inside Suspense; search inputs are URL params (q, tier, near) so back/forward and shared links re-run searches (page.tsx:2651-2653, 3030)
- Premium is gated client-side by probing GET /api/alerts (200 => premium, 403 premium_required => free, anything else => unknown) and the page silently falls back to /api/search/free when not entitled; the API enforces entitlement independently (page.tsx:2698-2726, 2930)
- Free searches are not delayed by the entitlement probe, but the search effect lists accountPlan and account.userId as dependencies so it re-runs when auth resolves (page.tsx:3030)
- Results are interleaved round-robin across sites, then the default 'relevanță' sort restores backend global rank via item.rank (search-data.ts:795-806; page.tsx:196-200, 3111); backend rank is global across sites (src/aggregate.js:1129-1142)
- Filters persist in localStorage v3; sources not in the curated SOURCES_LIST are never filtered out so newly added experimental adapters stay visible (page.tsx:3095-3097)
- Feedback dislikes hide the listing plus siblings sharing 'signature tokens' derived from title tokens not in the query; session-only, undoable, then POSTed to /api/feedback with query understanding and listing features (page.tsx:224-253, 2734-2805)
- Favorites and activity history are localStorage-per-user-id only (ui/src/lib/account-data.ts), gated by login but never synced to Supabase; the UI itself labels them 'salvate local' (page.tsx:3184)
- Only OLX CDN images are proxied through /api/image; all other hosts are hotlinked, with per-card fallback across item.images on error (search-data.ts:741-771; page.tsx:1468-1495)
- The 'Best Used Deal' vs 'Top Match · Verifică' label is driven by item.recommendation.strong rather than summary.recommendationMode (page.tsx:1949; backend sets both from the same flag, src/aggregate.js:1256)
- The new-price benchmark card is chosen client-side as the cheapest priced new-source item (including the API's bestNewBenchmark) after source/feedback filters, and savings are computed locally from displayed prices (page.tsx:2113-2116, 3120-3129)
- Vehicle UX (buyer journey, trust checklist, dealer snapshot, compare tray, price history) is enabled by a client keyword list (page.tsx:160-171), not by summary.queryUnderstanding.category
- Loading overlay is a simulated progress model (timer curve to 97%, hardcoded per-source windows, rotating status words) layered over a single request/response (page.tsx:77-121, 986-1104, 2910-2919)
- WhatsApp outreach message text is generated client-side and identifies itself as an AI assistant with an opt-out line; phone comes from /api/marketplace/contact, then item.sellerPhone, then window.prompt (page.tsx:310-324, 1523-1540)
- EmailCapturePopup is only enabled for logged-in users with results (page.tsx:3198-3203)

## Risks and smells

- **high** `ui/src/app/search/page.tsx:3030` — The search effect depends on accountPlan and account.userId. accountPlan transitions checking -> free/premium/unknown after useAccountSession and the /api/alerts probe resolve (page.tsx:2644-2650, 2698-2722), so a Free search started with accountPlan='checking' is aborted (page.tsx:3025-3029) and re-issued once for signed-out users and twice for signed-in users; the loader visibly resets to 8% (page.tsx:2905). Each restart is a new /api/search/free fan-out; server-side cancellation on client abort is not guaranteed.

## Test coverage

The root `npm test` glob (package.json: `node --test src/*.test.js src/parsers/*.test.js src/providers/*.test.js`) never touches ui/src/app/search or ui/src/components; the only root test importing from ui is src/auth-ui.test.js, which covers ui/src/lib/auth-flow.mjs (auth helpers, unrelated to search).
