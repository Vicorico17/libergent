# Subsystem map: Search execution, source registry, query understanding

Generated 2026-09-16 by a read-only code-reading agent. Evidence is `path:line` on commit 81c8e23. Claims were not independently re-verified unless noted in the [summary](../audit-2026-09-16.md).

## Summary

This subsystem turns one user query into per-site HTTP fetches, parses the HTML locally, applies a first-pass token filter, and paginates. Entry is runSearch (src/search.js:405), called per site by app.js:175 (searchSiteOnce) and by the validate-shops runner (src/shop-validation.js:53). runSearch normalizes the query (normalizeMarketplaceQuery, src/query-normalization.js:12), resolves the provider (src/provider-options.js:9; site.provider is "direct" for all 117 registered sites, verified by probe), and calls runSinglePageSearch (src/search.js:293), which builds the URL from site.searchUrl/pagedSearchUrl, fetches with two browser-like header profiles and a status-based retry list (src/search.js:123-238), dispatches to a per-site parser via parseSiteHtml (src/site-html-parser.js:11), stamps sourceType/condition/sellerType defaults (src/search.js:260), and filters titles with filterRelevantItems (src/search.js:93; single-token exact/prefix/1-edit match, mandatory numeric tokens, 0.5 weighted coverage with a 1.5 brand bonus). Multi-page runs (src/search.js:418-500) estimate total pages from totalResults, stop on hasNextPage=false/empty/no-new/short pages, and report exhaustedReason and pageError. Successful Vinted HTML is cached in caches.default for 300s under a synthetic libergent.com key (src/search.js:171-196); Cloudflare challenge responses (cf-mitigated header) fail fast at src/search.js:229 and the Vinted delayed retry lives in app.js:201-258, not here. The registry src/sites.js declares 117 adapters (12 Free, 105 unique Premium; PREMIUM_SITE_KEYS has 114 entries with 9 duplicates) with per-site URL builders, page sizes, timeouts and niche tags; 82 of them are generated from a guessed Magento "/catalogsearch/result/?q=" template (src/sites.js:1143-1158). Routing is keyword-heuristic: isCarQuery (src/sites.js:245) combines CAR_KEYWORDS substring matching, year/variant regexes and understandMarketplaceQuery's vehicle make list; niche predicates (src/sites.js:295-320) use raw substring includes over keyword lists; getSiteKeysForAllSearch (src/sites.js:1212) picks Free sources and getPremiumSiteKeys (src/sites.js:322) always adds the 7 PREMIUM_CORE retailers plus niche and experimental groups. src/query-understanding.js:131 produces a deterministic profile (category, make/model, canonicalPath, comparableKey, confidence) from a small data table of ~30 vehicle entities, 7 product families and 50 vehicle makes; it feeds Autovit path building (src/sites.js:223), isCarQuery, relevance.js, aggregate.js and mock.js. src/source-validation-snapshot.js is a hand-reviewed JSON dump of the 2026-09-15 validate-shops run plus production checks; src/sites.js:1194-1198 uses its repeatedNoUsefulResults flag to label sites "active" (9) or "experimental" (108), and src/source-catalog.js:6 exposes that plus tier/selection/evidence at /api/sources. integrationStatus is informational only: worker.js/server.js never filter on it, so "experimental" Free sources (anuntul.ro, price.ro, shopmania.ro) are still searched on every Free query (asserted by src/source-catalog.test.js:13-16). src/shop-validation.js:113 runs two live queries per site with an 8s timeout and 4-way concurrency and aggregates through aggregateMarketplaceResults to count final accepted offers. src/abort.js composes caller and timeout signals; src/shop-suggestions.js validates the shop-suggestion API body.

## Notable design decisions

- All registered sites are provider "direct" with local HTML parsers; remote providers (cloudflare/firecrawl) exist only as explicitly requested or auto-fallback paths (src/sites.js registry, src/search.js:269-274, app.js:97-108). README 'Reliability and provider policy' matches this.
- Integration status is derived at import time from a checked-in validation snapshot (src/sites.js:1194-1198) and is informational only; routing never consults it, so demoted Free sources are still fetched every query (src/source-catalog.test.js:13-16 asserts this deliberately).
- Query filtering is two-stage: search.js does a cheap token-coverage filter (src/search.js:93-121) and defers accessory/variant rejection to relevance.js/aggregate.js; okazii.ro opts out via disableQueryFilter (src/sites.js:581) and autovit.ro falls back to unfiltered items when the filter empties the page (src/search.js:358-360).
- Direct fetch never retries a Cloudflare challenge (src/search.js:229-231); Vinted-specific delayed retry is implemented one layer up in app.js:201-258, matching README lines 175-177.
- Only Vinted responses are cached, keyed on a synthetic https://libergent.com/api/internal-cache/direct-html/v1?url=... request so the Worker cache namespace stays first-party (src/search.js:171-177).
- Routing is keyword-table driven rather than model-driven: niche predicates are substring matches over Romanian keyword arrays (src/sites.js:179-221), vehicle detection mixes keyword, regex and the query-understanding make list (src/sites.js:245-284).
- The experimental retailer batch is data-only so health checks can promote or drop stores without touching routing code (comment at src/sites.js:120-121); 82 adapters share one guessed Magento URL template (src/sites.js:1143-1158).
- Pagination is capped per site by maxPages and by runtime: app.js:15 CLOUDFLARE_WORKER_MAX_PAGES_PER_SITE=1, so multi-page logic in runSearch only runs locally/CLI.
- Credit accounting (estimatedCreditsPerPage, creditsUsed) is retained from the Firecrawl era but every site sets 0 (src/sites.js:348,371,...; src/search.js:414,499).
- Source validation counts final accepted offers after aggregateMarketplaceResults rather than raw parsed cards (src/shop-validation.js:61-62), so accessory-only pages count as no useful results (src/shop-validation.test.js:5-15).

## Risks and smells

- **high** `src/sites.js:245` — isCarQuery over-triggers: CAR_KEYWORDS are matched as substrings of the joined token string (line 270 `joined.includes(keyword)`), so 'electric' hits 'chitara electrica'/'periuta electrica'/'boxa electrica', 'combi' hits 'combina frigorifica', 'auto' hits 'aspirator automat'/'autocolant', 'diesel' hits 'parfum diesel'; line 279 year+variant-code rule makes 'samsung galaxy s24 2024' a car query. Probe confirmed all of these return true. Car routing (line 1213-1222) then drops vinted.ro/price.ro/shopmania.ro and adds Autovit/BestAuto for tech queries, contradicting the tech-first direction.
- **high** `src/query-understanding.js:107` — findVehicleMake treats any whole-word occurrence of a make as vehicle intent with confidence 0.9; VEHICLE_MAKES includes 'smart', 'ds', 'mini', 'mg', 'seat', 'tesla', 'polo'-adjacent makes (lines 16-23). Probe: 'smart tv samsung 55', 'nintendo ds', 'mini frigider', 'ibuprofen 400 mg', 'seat cover' all yield category 'vehicle'. This profile feeds isCarQuery (sites.js:271-273), relevance.js and aggregate.js, so mis-typed tech queries can be routed and scored as vehicles.
- **medium** `src/sites.js:303` — matchesNiche and isFashionQuery use raw substring includes over keyword lists, with short keywords such as 'pat', 'masa', 'raft', 'flex', 'role', 'surf', 'schi', 'cort', 'yoga', 'carte', 'roman', 'manual', 'vans', 'hm', 'wc'. Probe: 'schimb iphone' and 'microsoft surface' -> sport; 'husa compatibila iphone' -> home; 'dacia logan romania' and 'cutie manuala' -> books; 'apartament cu avans' -> fashion; 'cablu flexibil' -> DIY. Each false positive fans a Premium search out to 3-11 extra retailers (lines 325-333), most of which 404 per the snapshot, adding latency and wasted fetches.
- **medium** `src/sites.js:1152` — 82 of 117 adapters are generated from one guessed Magento URL template `https://www.${key}/catalogsearch/result/?q=` with auto-derived labels ('ccc', 'librarie.net') and even non-.ro hosts (thomann.de, ccc.eu, deichmann.com). The snapshot records 404/403/challenge for the large majority; these are registered, counted in the public '117 adapters' figure and searched on Premium queries without any health gating.
- **medium** `src/sites.js:1194` — integrationStatus is computed from a checked-in snapshot at import time but never consulted by routing (worker.js/server.js do not read it). anuntul.ro, price.ro and shopmania.ro are labeled 'experimental' yet remain in FREE_DEFAULT_SITE_KEYS (lines 76-85) and are fetched on every Free query; price.ro failed both local and production checks in the snapshot. The public status is therefore decoupled from what users actually get.
- **medium** `src/server.js:316` — Local Premium path uses getPremiumSiteKeys(query) without deduplication while worker.js:883 wraps it in a Set. getPremiumSiteKeys returns duplicates (probe: 23 keys/22 unique for a home query; evomag.ro appears twice for tech queries because it is in both PREMIUM_CORE_SITE_KEYS and EXPERIMENTAL_EXPANSION.tech, sites.js:92,127), so the Node server searches the same site twice and reports inflated premiumMarketplaces.
- **medium** `src/search.js:155` — fetchHtmlDirect retries immediately with a second spoofed header profile on 403/406/429/5xx (lines 206-235) with no backoff; a 429 rate-limit is retried at once and the mobile profile lies about Referer 'https://www.google.com/' and Sec-Fetch-Site 'cross-site' (lines 143-151). This is anti-bot evasion behaviour that can escalate blocking and conflicts with README's 'never use ... as an anti-bot bypass' framing for browsers.
- **medium** `src/shop-validation.js:31` — VALIDATION_TIMEOUT_MS is 8s but registered site timeouts are 12-25s (sites.js:436,466,890 etc.) and runSearch passes site.timeoutMs to fetchHtmlDirect; slow-but-working sources are recorded as 'Validation timed out after 8s.' (egradini.ro in the snapshot) and demoted to fix_or_demote. Validation is also a live-network command run at 4-way concurrency across up to 117 origins with no per-host politeness.
- **medium** `src/source-validation-snapshot.js:3` — A 53KB hand-edited data file imported at runtime by sites.js and source-catalog.js. It is the sole input to integrationStatus, has no schema validation, no generator script (cli validate-shops writes JSON elsewhere and does not update it), and its repeatedNoUsefulResults values for olx.ro/okazii.ro were manually overridden based on productionChecks that runShopValidation never produces. Drift between the file and reality is silent.
- **low** `src/sites.js:136` — PREMIUM_SITE_KEYS contains 114 entries but only 105 unique (duplicates: altex.ro, intersport.ro, evomag.ro, notino.ro, animax.ro, petmart.ro, zooplus.ro, mcmusic.ro, soundcreation.ro). Consumers use includes() so it works, but the count is misleading and sites.test.js:103-106 only passes because it wraps in a Set.
- **low** `src/sites.js:442` — OLX searchUrl inserts the raw query into the URL path after only replacing whitespace with dashes (slugifySpacesWithDash, line 5); '?', '#', '/' and non-ASCII pass through. Probe: query 'a?b#c /x' yields https://www.olx.ro/oferte/q-a?b#c-/x/?search%5Border%5D=..., which injects a query string and truncates the intended sort parameter. Host is fixed so this is not SSRF, but arbitrary query text can alter the OLX request.
- **low** `src/search.js:179` — readDirectHtmlCache awaits cache.match without try/catch (writeDirectHtmlCache does catch); a throwing Cache API would fail the whole Vinted search instead of falling through to the origin fetch.
- **low** `src/search.js:171` — Vinted cache key uses the full target URL including page number but the TTL is a fixed 300s regardless of the origin's Cache-Control; cached HTML is served even for logged-out personalised pages, and there is no cache-bypass for the health page or validate-shops, so repeat probes within five minutes report stale results (snapshot records cacheHit only at the API layer, not here).
- **low** `src/search.js:115` — Brand bonus lets a brand-only match pass the 0.5 coverage threshold for three-token queries: probe shows 'Nike Dunk Low' survives the filter for query 'nike air force' (1 token + 1.5 brand = 2.5 / 4.5). Downstream relevance must catch it; the first-stage filter is weaker than the README stage-2 description implies.
- **low** `src/search.js:34` — tokenDistanceAtMostOne is an ad-hoc edit-distance that treats transpositions as two edits and accepts a one-character deletion at either end; with the length>=5 gate (line 85) it matches 'rowneta' to 'rowenta' only because of the substitution path. Untested edge cases (both strings differing at index 0, trailing char) are covered only by one test.
- **low** `src/shop-validation.js:131` — Hardcoded per-site query overrides for avstore.ro and a2t.ro embedded in the runner instead of the registry; adding another exception requires editing routing code, contradicting the data-not-code intent stated at sites.js:120-121.
- **low** `src/provider-options.js:22` — isProviderConfigured defaults env to globalThis.process?.env; in the Cloudflare Worker process is undefined so remote providers are always 'unconfigured' unless an env is passed, while app.js:105 calls it without env. Combined with app.js:104-107 auto-fallback this makes provider behaviour runtime-dependent and hard to reason about.
- **low** `src/abort.js:36` — Fallback path (no AbortSignal.any) adds 'abort' listeners to caller signals and never removes them on completion; for long-lived caller signals (one per request across many sites) listeners accumulate until the request ends. Node 22 has AbortSignal.any so the path is dormant but untested.
- **low** `src/shop-suggestions.js:1` — URL_PATTERN rejects hosts with ports and any userinfo but accepts arbitrary path characters; 'niche' is free text lowercased to 40 chars and not checked against NICHE_CATALOG; 'note' up to 800 chars is stored verbatim. No HTML/markdown neutralisation is performed here, so any rendering of suggestions must escape.
- **low** `src/sites.js:1163` — SITE_NICHE_KEYS duplicates niche membership already implied by the PREMIUM_*_SITE_KEYS and EXPERIMENTAL_EXPANSION tables and mutates SITES entries after construction (lines 1176-1186), so niche tags and tier lists can drift; compari.ro is tagged 'marketplaces' here but treated as 'tech' by shop-validation.js:37.
- **low** `src/sites.js:598` — publi24.ro is the only site with defaultMaxPages 11 and defaultLimit 330 (lines 609-611); on the local/CLI runtime a single Free query fetches up to 11 Publi24 pages sequentially (search.js:438-474) while every other site fetches one, making Publi24 the latency floor for local searches and validate-shops.
