## Summary

This area is the outbound-fetch and browser-automation layer beneath LiberGent's search pipeline, plus three small side modules (OLX image proxy, an image-search stub, a consent-gated call pipeline) and the offline mocks. Four providers live in src/providers: cloudflare-browser.js drives Cloudflare Browser Rendering through @cloudflare/puppeteer (installed 1.3.0, whose types declare Browsers='kitesurf') with a selectable engine (chromium, or kitesurf via launch(binding,{browser:'kitesurf'}) at src/providers/cloudflare-browser.js:15-19), exposing revealOlxPhonesWithBrowser (navigate to an OLX listing, auto-click an 'Acceptă' consent button, click the 'show phone' control by coordinates, capture the /offers/{id}/...phone JSON response, else scrape rendered text and classify captcha/verification/login signals; lines 28-157), searchMarketplaceWithBrowser / searchMarketplacesWithBrowser (render site.searchUrl, run the same parseSiteHtml + filterRelevantItems used by direct fetch, tolerate navigation timeouts when the DOM already parsed cards, flag challenge pages by regex, share one browser across a bounded worker pool; lines 194-323) and benchmarkMarketplaceWithBrowser (159-192). cloudflare.js and firecrawl.js are thin REST clients (Cloudflare browser-rendering /json and /crawl; Firecrawl v2 /scrape in JSON and markdown modes) that read credentials from process.env via requireEnv and are invoked only from src/search.js:317-350 when the resolved provider is 'cloudflare' or 'firecrawl'. openclaw.js is a WhatsApp bridge client that no runtime module imports; src/worker.js:1245-1258 re-implements the same POST inline. provider-options.js defines the provider enum (auto/direct/firecrawl/cloudflare), the auto-fallback order (cloudflare, firecrawl) and a credential-presence check that src/app.js:92-111 uses to append configured remote providers after a failed direct fetch. mock.js fabricates three deterministic listings per site (vehicle-aware) when LIBERGENT_MOCK_SEARCH=1 (src/app.js:395-398), while cloudflare.js has its own LIBERGENT_MOCK_PROVIDER short-circuit returning hardcoded 'iPhone 15 Pro' rows (src/providers/cloudflare.js:8-62); Firecrawl has no mock path. Worker data flow: /api/search/premium runs direct fetch for free+premium site keys, then Kitesurf for every eligible site whose direct result is not ok or has zero items (limit defaults to the eligible count), then Chromium for a fixed allowlist (okazii.ro + compari/pcgarage/flanco/altex, default limit 5), preferring the first result with items; challengeDetected results are downgraded to ok:false (src/worker.js:335-362, 883-957). /api/marketplace/contact chains OLX phone API -> HTML regex -> Chromium reveal (src/worker.js:708-737) and is cached 15 minutes per listing URL. /api/image proxies only https *.olxcdn.com targets (unwrapping www.olx.ro/_next/image) with a byte cap on both the Worker and the Node dev server, and the UI mirrors the allowlist in TypeScript. /api/image-search validates MIME/size then always returns 501 because extractImageSearchIntent is a stub. call-pipeline.js turns listings with extractable Romanian mobile numbers into pending_approval jobs only when consent is asserted and exposes a placeCall boundary that nothing wires to a telephony provider; src/outreach.js consumes only assertCallJobCanRun and is itself not imported by worker/server. All 117 registry sites are provider 'direct' with direct-html-local/retail strategies (verified by importing src/sites.js), so the crawl-seed and firecrawl-markdown-local branches in search.js are unreachable from the registry and the REST providers are reachable only via an explicit provider= parameter or Node-side auto-fallback when credentials exist. Worker bindings are copied into process.env by applyEnv (src/worker.js:48-62) so the process.env-based providers and isProviderConfigured work on Cloudflare.

## Notable design decisions

- Browser adapter takes an injectable `launch` and optional shared `browser` so every path is unit-testable without puppeteer (src/providers/cloudflare-browser.js:28,162,197,281); Kitesurf is selected solely by launch(binding,{browser:'kitesurf'}) (15-19)
- Browser-rendered HTML is parsed by the same parseSiteHtml + filterRelevantItems used for direct fetch, so no site needs a browser-specific parser (src/providers/cloudflare-browser.js:231,241)
- Navigation timeouts are tolerated when page.url() left about:blank and the DOM already yields rawItemCount>0; otherwise the timeout is rethrown (src/providers/cloudflare-browser.js:212-234). README:175 describes this as Altex-specific but the code is generic
- Challenge detection is a regex heuristic over visible body text (only when includeBodyText) and the first 30KB of HTML; the Worker converts challengeDetected into ok:false so challenged pages never count as results (src/providers/cloudflare-browser.js:238-240; src/worker.js:348-351)
- Multi-site browser search shares one browser across a worker pool (concurrency clamp) and reports browserSessionsUsed=1 only on index 0 so summaries count sessions, not pages (src/providers/cloudflare-browser.js:278-322)
- Premium policy is layered: direct for all sites -> Kitesurf for every eligible site with a failed/empty direct result (default limit = eligible count, concurrency 4, kill switch PREMIUM_KITESURF_ENABLED) -> Chromium only for okazii.ro + PREMIUM_BROWSER_SITE_KEYS (default limit 5, concurrency 3); preferBrowserFallback keeps the first result with items (src/worker.js:35-42,74-100,883-918)
- Free API maps provider=auto to direct and Premium hardcodes direct for the first pass, so automatic remote REST providers only run in the Node CLI/dev path (src/worker.js:821,887-888; src/app.js:104-108)
- OLX phone reveal is a three-tier chain (OLX phone API -> HTML regex -> Chromium click) where the browser tier auto-dismisses the consent dialog and clicks by computed coordinates, then classifies captcha/verification/login signals for the UI (src/worker.js:708-754; src/providers/cloudflare-browser.js:39-64,71-153)
- Image proxy is a strict allowlist (https + olxcdn.com only, OLX optimizer unwrapped) with content-type check, content-length precheck, streaming byte cap on the Worker and buffered cap on Node, 24h public cache and CORS * (src/image-proxy.js; src/worker.js:364-416; src/server.js:91-140)
- Calling is deliberately not implemented: jobs are only built when consented, run only when approved and status==='approved', and placeCall is injected; .env.example:33-37 says a provider must be chosen first (src/call-pipeline.js:9-13,39-58)
- REST providers read process.env, not the Worker env argument; the Worker bridges every string binding into globalThis.process.env in applyEnv before routing (src/worker.js:48-62,757)
- Two independent mock switches: LIBERGENT_MOCK_SEARCH replaces the whole search with mock.js listings (src/app.js:395), LIBERGENT_MOCK_PROVIDER replaces only Cloudflare REST responses with hardcoded iPhone rows (src/providers/cloudflare.js:4-62); both default to 1 in .env.example:26-27
- The site registry (117 entries, all provider 'direct', 10 direct-html-local + 107 direct-html-retail, verified by importing src/sites.js) makes crawl-seed and firecrawl-markdown-local branches unreachable; only altex.ro and flanco.ro set browserWaitUntil/browserWaitForMs and only okazii.ro sets disableQueryFilter
- The Worker re-implements the OpenClaw bridge POST inline instead of importing src/providers/openclaw.js (src/worker.js:1245-1258 vs src/providers/openclaw.js:12-22)
