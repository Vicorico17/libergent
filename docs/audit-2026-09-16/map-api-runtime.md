# Subsystem map: Worker/Node runtime, routing, auth/entitlements, env, API surface, health

Generated 2026-09-16 by a read-only code-reading agent. Evidence is `path:line` on commit 81c8e23. Claims were not independently re-verified unless noted in the [summary](../audit-2026-09-16.md).

## Summary

The backend has two hand-written HTTP routers with no framework: the production Cloudflare Worker (src/worker.js, `export default { fetch, scheduled }`) and a Node dev server (src/server.js, `http.createServer`). Both dispatch on a trailing-slash-normalized pathname through a long if-chain; anything not under /api/ is served as a static asset (Worker: `env.ASSETS.fetch` at worker.js:1441; Node: file lookup under ui/out at server.js:574-580). The Worker exposes 21 distinct API paths (enumerated in entryPoints) in four auth classes: public (sources, image proxy, free search, history, leads, saved-searches, shop-suggestions, image-search stub, vehicle price history, marketplace details, marketplace contact), Supabase-session (feedback, conversations, whatsapp/send), Supabase-session + Premium entitlement (search/premium, all /api/alerts*), and static admin token (health/sources, admin/alerts/run, admin/browser-benchmark, admin/shop-suggestions), plus a bearer-token webhook for OpenClaw inbound WhatsApp. Session auth is a per-request `GET {SUPABASE_URL}/auth/v1/user` with the Worker's service/anon key as apikey and the user's bearer token (worker.js:274-292); entitlement is read from `user_entitlements` via PostgREST unless the email is in `LIBERGENT_PREMIUM_EMAILS` or `LIBERGENT_PREMIUM_ALERTS_BETA=1` short-circuits it (supabase.js:403-418). Search flow: `getSearchRequestParams` validates q/limit/pages (api-params.js caps: limit 240, pages 4), `resolveViewerLocation` derives a coarse city from `request.cf`/`near=`, a Cache API key is built per tier/query/filters/location/mock (worker.js:117-128), and on miss `searchAcrossSites` (src/app.js) fans out with concurrency 3, two attempts per site, provider-candidate fallback, per-site timeouts, and a Worker-only cap of 1 page/site (app.js:15,172-174) before `aggregateMarketplaceResults` ranks. Free search forces provider auto->direct (worker.js:821); Premium runs direct for free+premium sites in parallel, then Kitesurf for every empty/failed eligible site, then Chromium for a 5-site allowlist (okazii + PREMIUM_BROWSER_SITE_KEYS), all bounded by PREMIUM_* env knobs (worker.js:74-100, 883-957). Persistence is a thin PostgREST client in src/supabase.js (`requestSupabase`) that takes an explicit `env` argument in the Worker and defaults to `process.env` in Node; `applyEnv` also copies every string Worker secret into a global `process.env` so modules like providers/cloudflare.js and firecrawl.js can read credentials (worker.js:48-62). Search events, vehicle price observations, feedback, leads, saved searches, WhatsApp messages, alerts, and notification deliveries are all written through that client; history reads come from search_events plus two stats tables. Premium vehicle alerts run from the hourly cron (`15 * * * *`, wrangler.toml:14): `runDuePremiumAlerts` loads up to 20 due profiles, re-checks entitlement, searches autovit+bestauto only (worker.js:504), diffs against `alert_listing_state`, inserts deduped events, and posts email through an optional generic webhook. The Node server mirrors only 13 of the Worker's routes, never uses the Cache API or BROWSER binding, honors `provider` verbatim, and additionally writes history to a local data/search-history.json. Env is loaded from .env.local/.env by src/env.js in Node; in the Worker it comes from bindings/secrets, with `OPENCLAW_BRIDGE_URL` the only committed var. Deployment is `npm run deploy` (build UI, verify NEXT_PUBLIC_SUPABASE_* are embedded in the bundle, `wrangler deploy`) driven by .github/workflows/deploy-cloudflare.yml on push to main. Test baseline for this area: 35/35 pass across worker/supabase/app/api-params test files (verified offline this session).

## Notable design decisions

- Two hand-rolled routers (Worker + Node) instead of one shared handler; Worker is the source of truth and the Node server is an intentionally reduced mirror (README:277, :185) — already drifted by 8 routes
- Worker secrets are copied into a mutable global process.env on every API request (applyEnv, worker.js:48-62) so runtime-neutral modules can read credentials via process.env; Supabase helpers additionally accept an explicit `env` argument that defaults to process.env for Node (supabase.js:33, 114)
- Auth is delegated entirely to Supabase: no local JWT verification, every authenticated request round-trips to /auth/v1/user (worker.js:274-292); Premium entitlement is a second PostgREST read per request with email allowlist and a global beta flag as overrides (supabase.js:403-418)
- Admin operations use a single shared static token accepted from Bearer, custom header, or query string (worker.js:265-272)
- Search snapshots are cached in the Cloudflare Cache API for 5 min keyed by tier/query/condition/provider/site/limit/pages/coarse location/mock flag; only responses containing at least one ok result with items are cached (worker.js:117-154); contact 15 min, details 30 min
- Free tier: provider auto is remapped to direct, never touches BROWSER (worker.js:821). Premium: direct for free+premium sites in parallel, then Kitesurf across all empty/failed eligible sites (default limit = all, concurrency 4), then Chromium for okazii + 4-site allowlist (default limit 5, concurrency 3), with PREMIUM_KITESURF_ENABLED as instant rollback (worker.js:35-100, 883-957)
- In the Worker runtime app.js caps every site to 1 page and 500 results (app.js:15, 13, 172-176) regardless of requested pages; timeouts are shortened to 30 s per site (app.js:14, 141-146)
- Premium alerts are vehicle-only by construction (worker.js:504 searches only autovit.ro/bestauto.ro; alerts.js criteria are price/year/mileage/location), run sequentially in the hourly cron with a 20-profile batch, first check only baselines (eventsToInsert=[] when last_checked_at is null, worker.js:510), and 'immediate' frequency means hourly re-check (supabase.js:534)
- Search analytics writes (search_events RPC, vehicle price observations) are awaited inline in the request path rather than deferred with context.waitUntil (worker.js:828, 842-843, 960-961); cache writes are deferred (worker.js:152-153)
- Marketplace fetches on behalf of users are SSRF-guarded by an allowlist of SITES hostnames (and subdomains) + https, re-validated on each manual redirect hop (worker.js:218-255); image proxy is limited to olxcdn.com (image-proxy.js:32-46)
- WhatsApp outbound is executed by the Worker directly against the OpenClaw bridge and mirrored into whatsapp_messages with raw.userId as the ownership key; inbound ownership is resolved by unique prior outbound sender and left unassigned when ambiguous (supabase.js:616-626)
- Deploy pipeline gates on the UI bundle actually containing the public Supabase config (scripts/verify-ui-auth-config.js) so a build without auth config cannot ship
- Errors are mapped to HTTP status by string-matching error messages ('Missing q parameter', startsWith('Expected '), 'Unsupported site', 'Unsupported provider', includes('large'), includes('not configured')) (worker.js:850-854, 966-970, 1104, 1123, 1426)

## Risks and smells

- **high** `src/server.js:219` — Router logic is duplicated by hand between src/server.js and src/worker.js and has already drifted: the Node server lacks /api/openclaw/inbound, /api/admin/alerts/run, /api/admin/browser-benchmark, /api/conversations, /api/whatsapp/send, /api/vehicle/price-history, /api/marketplace/details and /api/marketplace/contact, so under `npm run dev` the UI's calls to those paths (ui/src/app/search/page.tsx:1526,1545,2220,2240; ui/src/components/AccountDashboard.tsx:200) fall through to the static handler and receive a text 404 (server.js:574-580, 183-186). Free-search provider policy also differs (server.js:270 passes provider through; worker.js:821 forces direct) and entitlement-service failures map to 503 here but 403 in the Worker.
