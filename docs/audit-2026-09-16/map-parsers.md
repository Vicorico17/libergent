# Subsystem map: Marketplace and retail HTML parsers (src/parsers/*, src/site-html-parser.js, dispatch from src/search.js)

Generated 2026-09-16 by a read-only code-reading agent. Evidence is `path:line` on commit 81c8e23. Claims were not independently re-verified unless noted in the [summary](../audit-2026-09-16.md).

## Summary

The parsers subsystem turns raw marketplace/retail search-page HTML into a uniform listing shape without any DOM library: every parser is a set of regexes and string slicing over the page, which keeps the code dependency-free and Cloudflare-Worker compatible. The single dispatcher is parseSiteHtml in src/site-html-parser.js:11-47, a hardcoded if/else on site.key (lajumate, okazii, olx, vinted, publi24/bestauto, autovit, anuntul, emag, evomag, flip, klap) with one strategy-level fallback (site.strategy === "direct-html-retail" -> parseRetailHtml) and a throw for anything else. It is invoked from two places: src/search.js:312 inside runSinglePageSearch after fetchHtmlDirect succeeds for the "direct" provider (the only provider any registered site uses; sites.js contains 10 direct-html-local and 17 direct-html-retail strategies and nothing else), and src/providers/cloudflare-browser.js:231 on browser-rendered page.content() during Premium fallback. Every parser returns {items, totalResults, rawItemCount, hasNextPage}; items carry title, a raw price string, a loosely-cased currency, location, postedAt, condition, sellerType, url, imageUrl and sometimes imageUrls; numeric price/currency normalization is deferred to src/normalize.js (verified that "3199.99 RON", "3.199,00 lei", "4.700 RON", "2 450 lei", "32 500 EUR" all normalize correctly). search.js then applies site metadata defaults (search.js:260-267), runs filterRelevantItems unless site.disableQueryFilter (Okazii, sites.js:581), special-cases Autovit to keep unfiltered items when the filter empties the list (search.js:358-360), and drives pagination using the parser's totalResults/rawItemCount/hasNextPage (search.js:377-403, 438-474). Site-specific strategies: OLX slices data-cy="l-card" cards and lazily recovers images from the escaped __INIT_CONFIG__ JSON when a card has no thumbnail (olx.js:104-123, 281-285); Vinted slices data-testid="grid-item" and extracts title/price/condition from the anchor title attribute (vinted.js:92-120); Lajumate parses __NEXT_DATA__ props.pageProps.adsServer and is the only parser that throws instead of returning empty (lajumate.js:7-14, 39-46); Okazii tries "lising-old-li" cards then falls back to JSON-LD Product.offers.offers (okazii.js:193-209); Publi24's article-item parser is reused for BestAuto via an origin option (publi24.js:101, site-html-parser.js:21-22); Autovit slices <article> blocks or windows around /autoturisme/ links and back-fills missing prices from JSON-LD by index (autovit.js:40-56, 166-188); Anuntul parses .itm cards with tag-derived condition/sellerType (anuntul.js:99-126); Flip fetches the whole catalog and filters locally against the query inside the parser (refurbished.js:70-108); Klap parses WooCommerce cards preferring <ins> sale price (refurbished.js:110-166); eMAG reads the data-product JSON attribute (retail.js:241-272); evoMAG and the generic retail parser use anchor-plus-nearby-price heuristics, JSON-LD, and ".produs-lista" blocks (retail.js:96-230, 281-368). A shared helper, extractImageCandidate (image.js:40-76), picks lazy-load attributes, then src, then the largest srcset candidate, rejecting data: URIs and known placeholders. The markdown parsers parseOlxMarkdown/parseVintedMarkdown and the firecrawl/crawl-seed branches in search.js are unreachable because no registered site uses those strategies. Test coverage is 18 passing tests over synthetic inline HTML (verified with node --test src/parsers/*.test.js); there are no real-page fixtures, no tests for Autovit, Vinted HTML, evoMAG, the Okazii card path, or the dispatcher itself, and the docs already record several sources returning 0/0 with "investigate query/parser".

## Notable design decisions

- Pure regex/string-slicing parsers with no HTML DOM library, so the same code runs in the Cloudflare Worker, Node dev server, CLI, and browser-fallback path (all parser files; site-html-parser.js:1-9)
- One hardcoded dispatcher keyed on site.key with a strategy-level generic fallback for direct-html-retail; unknown direct-html-local sites throw at runtime rather than silently returning nothing (site-html-parser.js:13-38)
- Uniform parser contract {items, totalResults, rawItemCount, hasNextPage}; rawItemCount is meant to be the count of candidate cards before relevance filtering so the UI can show parsed-vs-matched (README.md:88-95, search.js:256-258, app.js:208-222) — but retail/refurbished parsers report rawItemCount = accepted items (retail.js:320-336,356-367; refurbished.js:161-165) so that distinction is lost for them
- Price is kept as the raw marketplace string plus a loosely-cased currency; numeric normalization and EUR->RON conversion are deferred to src/normalize.js (verified all emitted formats normalize correctly)
- OLX embedded-config image recovery is computed lazily and only when a card has no usable thumbnail (olx.js:207, 281-285); OLX bare numeric prices are assumed to be lei (olx.js:130-138, tested)
- Okazii tries visible search cards first and only falls back to JSON-LD offers; Okazii is exempt from the query filter via disableQueryFilter (okazii.js:193-209, sites.js:581)
- Flip deliberately fetches the whole /magazin/ catalog (pageSize 500) and filters in-parser to avoid the disallowed ?search= route (sites.js:504-507, refurbished.js:39-46,82-88, docs/marketplace-integration-todo.md:178)
- Klap and eMAG explicitly prefer structured/sale prices over crossed-out or installment text (refurbished.js:115-123, retail.js:253-255) with regression tests
- Publi24 parser is origin-parameterized so BestAuto (same network) reuses it (publi24.js:101, site-html-parser.js:21-22)
- Lajumate throws on missing __NEXT_DATA__/adsServer so a blocked page surfaces as a source error; every other parser returns an empty result on selector drift (lajumate.js:10,44)
- Autovit gets a special escape hatch in search.js:358-360: if the relevance filter drops everything, the unfiltered items are returned
- Shared extractImageCandidate prefers lazy-load attributes, then src, then the largest srcset width, and rejects data: URIs, no_thumbnail and /placeholder. (image.js:33-76)
- Each parser carries its own copy of decodeHtmlEntities/cleanText/stripTags/toAbsoluteUrl rather than a shared utility module (9 copies of decodeHtmlEntities, 8 of toAbsoluteUrl)

## Risks and smells

- **high** `src/parsers/retail.js:72` — Crash on legitimate JSON-LD: `const offer = Array.isArray(product.offers) ? product.offers[0] : product.offers || product;` yields undefined when offers is an empty array, then line 76 `offer.lowPrice` throws TypeError (verified locally: "Cannot read properties of undefined (reading 'lowPrice')"). The map at line 99 is not wrapped in try/catch, so parseRetailHtml throws and the whole source fails for any of the 15+ generic direct-html-retail sites whose page embeds a Product with "offers": [].
- **medium** `src/parsers/retail.js:159` — Anchor heuristic slices a window of 900 chars before / 5000 chars after each product link and findPrice (104-113) returns the FIRST lei/ron/eur amount in that window. Verified: a card containing "Transport 19 lei" before "2.499 lei" yields price "19 lei". Windows also overlap neighbouring cards, so titles, images and prices can be attributed to the wrong product. Same pattern in parseEvomagProducts (291-293) and autovit.js:50-55.
- **medium** `src/parsers/autovit.js:177` — JSON-LD price backfill uses `jsonLdOffers[index]` where index is the position AFTER parseListingBlock filtering (172), while JSON-LD order follows the unfiltered page order. Verified: when the first <article> is a category link and is dropped, the second listing receives the first JSON-LD price (1000 EUR instead of 2000 EUR). Wrong vehicle prices whenever any block is rejected.
- **medium** `src/parsers/okazii.js:112` — Price is the LAST `N,NN Lei` match in the card (`priceMatches.at(-1)`), so any later amount in the block (shipping, installment, previous price) wins. Verified with a synthetic card: "1.299,00 Lei" + "Transport 15,00 Lei" -> price "15,00 Lei". Whether live Okazii cards contain such trailing amounts is unverified.
- **medium** `src/parsers/olx.js:166` — hasNextPage is true whenever ANY href contains page=N, including the previous-page link on the last page (verified: `<a href="/oferte/q-x/?page=1">Anterior</a>` -> true). Vinted (vinted.js:79-81) matches `[?&]page=\d+` anywhere in the HTML including script text (verified true from a <script> string); anuntul.js:139-141, publi24.js:97-99 and okazii.js:160-162 use the same unanchored pattern. In search.js:385-403 a true hasNextPage suppresses the "no-new-listings" stop, so extra pages are fetched up to targetPages (bounded by estimateTotalPages, but unbounded-by-content when totalResults is null).
- **medium** `src/site-html-parser.js:37` — Selector drift is silent: every parser except Lajumate returns an empty items array when its regexes stop matching, and app.js:208-222 classifies rawItemCount 0 as an ordinary empty page, so a broken parser is indistinguishable from a genuinely empty search. There are no fixture-based regression tests or parse-health signals; docs/p0-progress-2026-09-15.md already lists several sources at 0/0 with 'investigate parser'.
- **medium** `src/parsers/vinted.js:103` — Vinted items are dropped entirely unless a price is present in the anchor `title` attribute (93, 103-106); if Vinted's grid markup stops embedding the price in that label, the source silently returns 0 items (README.md:484 already notes Vinted is fragile). Unverified against live markup.
- **low** `src/parsers/publi24.js:98` — `/[?&amp;]pag=\d+/` is a character class of `?`,`&`,`a`,`m`,`p`,`;` rather than the intended `&amp;` entity; works by accident because `&` is in the set (verified stray text "amp;pag=2" also returns true).
- **low** `src/parsers/olx.js:16` — decodeHtmlEntities/cleanText/stripTags/toAbsoluteUrl are copy-pasted into 9 parser files (plus listing-details.js) with divergent semantics: olx/vinted/okazii/autovit return schemeless relative paths unchanged, publi24/anuntul/retail prefix the origin, refurbished uses `new URL`; image.js:6-13 lacks &nbsp; and numeric-entity decoding that the others have. Any entity/URL bug must be fixed in nine places.
- **low** `src/parsers/olx.js:24` — Numeric entities are decoded with String.fromCharCode, which mangles astral code points (verified: `Tel &#128241;` -> "Tel " plus a lone surrogate). Same in vinted.js:24-25, okazii.js:20-21, publi24.js:11-12, autovit.js:11-12, anuntul.js:11-12, refurbished.js:11-12, retail.js:11-12. Titles with emoji lose characters and dedupe keys may differ across sources.
- **low** `src/parsers/olx.js:28` — toAbsoluteUrl in olx/vinted/okazii/autovit/anuntul/publi24 passes through arbitrary schemes (e.g. javascript:, data:) from marketplace hrefs; only retail.js:25 rejects javascript:/mailto:. Item URLs are rendered as links in the UI; whether the UI sanitizes schemes was not verified here.
- **low** `src/parsers/okazii.js:82` — LISTING_BLOCK_PATTERN is a module-level /g regex with manual lastIndex reset — shared mutable state; countListingBlocks (103-105) re-runs an identical literal regex, so the two can drift.
- **low** `src/parsers/image.js:2` — getAttribute builds `name\s*=\s*["']([^"']+)["']`: values containing the other quote character are truncated, and because the name is unanchored, `src=` can match inside an earlier `data-src=` attribute on the same tag (masked in practice because data-src is checked first).
- **low** `src/parsers/refurbished.js:39` — Flip carries its own matchesQuery relevance filter (no typo tolerance, no brand weighting) and search.js:357 applies filterRelevantItems on top, so two different relevance rules run sequentially for one source; also Flip fetches the entire catalog (pageSize 500, sites.js:504-507) on every tech query.
- **low** `src/site-html-parser.js:13` — Dispatcher is an if/else chain on literal site keys; adding a direct-html-local site without a branch throws 'No HTML parser configured' only at runtime, and no test (sites.test.js or search.test.js) asserts every direct-html-local site has a parser branch.
- **low** `src/providers/cloudflare-browser.js:241` — Post-parse metadata defaulting and relevance filtering are duplicated between search.js:355-361 (applySiteMetadata + filter + Autovit escape hatch) and cloudflare-browser.js:241-247 (which lacks the Autovit escape hatch), so direct and browser paths can produce different item sets from identical HTML.
- **low** `src/parsers/vinted.js:112` — Currency strings are inconsistent across parsers ("Lei", "lei", "RON", "EUR", ""), relying on normalize.js:17-29 to reconcile; the parser output contract is not documented or validated anywhere.
