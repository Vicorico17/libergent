## Summary

The UI is a Next.js 16 / React 19 app built as a static export (ui/next.config.ts:9-10, output: "export", trailingSlash: true) and served by the Cloudflare Worker's ASSETS binding from ui/out (wrangler.toml:6-8; src/worker.js:1437-1441 routes /api/* to handleApi and everything else to env.ASSETS.fetch). There is no server-side rendering of user state: every page in this area is either a pure marketing page or a "use client" page that fetches same-origin /api endpoints from the browser. The root layout (ui/src/app/layout.tsx) loads eight Google font families, sets site-wide metadata (canonical "/", robots index, OG image) and always mounts GoogleAnalytics with a hardcoded default measurement ID G-R8P7G7PWR7 when no env var is present (layout.tsx:60,132-135). The landing page (ui/src/app/page.tsx:52-70) composes Navbar → Hero → FeatureCards → HowItWorks → FeaturesGrid (testimonials) → Pricing → FinalCTA → Footer and injects Organization/WebApplication JSON-LD claiming price 0 RON (page.tsx:42-46). Marketing copy consistently names OLX, Vinted, LaJumate, Okazii, Publi24 and Autovit (layout.tsx:69, Hero.tsx:102-104, Footer.tsx:56-57) plus Price.ro/ShopMania as new-price benchmarks, while the Free registry per README.md:40-53 also includes Anuntul, BestAuto, Flip and Klap; the landing dashboards (Hero, HowItWorks, FeatureCards) render fabricated "live" telemetry (latencies, uptime 99.98%, 297 results, 92% confidence) as static constants. Pricing exists on two surfaces: the landing section (ui/src/components/sections/Pricing.tsx) shows Premium as "Blocat"/"Indisponibil momentan" with no CTA, whereas /pricing (ui/src/app/pricing/page.tsx) shows "În curând", "Testează căutarea Premium acum", a CTA to /search?tier=premium, "Fără card în perioada de test", "Anulare oricând" and a registry-backed SourceCatalog fetched from /api/sources; both read PREMIUM_MONTHLY_PRICE_RON = 99 from ui/src/lib/pricing.ts and no checkout/Stripe path exists anywhere in the UI. Authentication is entirely client-side through a lazily created supabase-js singleton (ui/src/lib/supabase-browser.ts:5-19, persistSession/autoRefreshToken/detectSessionInUrl) that returns null when NEXT_PUBLIC_SUPABASE_URL/PUBLISHABLE_KEY are absent; /auth, /signup and /reset all render the same SignInOptions component (ui/src/components/GoogleSignIn.tsx) offering Google OAuth and a passwordless email OTP with a 60 s client-side resend cooldown, redirecting to `${origin}/confirm?next=<safe path>`; /confirm (ui/src/app/confirm/page.tsx) verifies token_hash/type or exchanges a PKCE code, guards against React effect replay with a ref, then router.replace(next). The `next` parameter is sanitized by getSafeNextPath in ui/src/lib/auth-flow.mjs:30-33 (deliberately an .mjs so Node tests import it) and reused by buildAuthPath in ui/src/lib/auth-path.ts. /account (ui/src/app/account/page.tsx + ui/src/components/AccountDashboard.tsx) uses useAccountSession (ui/src/lib/use-account-session.ts) to gate a dashboard whose favorites, activity history and cached alerts live only in browser localStorage keyed by user id (ui/src/lib/account-data.ts), while alerts, alert events and seller conversations are fetched with a Bearer access token from /api/alerts, /api/alerts/:id, /api/alerts/events/:id and /api/conversations; Premium status is inferred from the /api/alerts response (403 code premium_required → Free) rather than a dedicated entitlement endpoint, and the same trick styles the Navbar's AccountNavLink (ui/src/components/AccountNavLink.tsx:15-34). /health (ui/src/app/health/page.tsx) is a public manual healthcheck that calls /api/search/free?site=all&limit=120 with a 120 s abort and renders per-source status, cache flags and counts. /trenduri (ui/src/app/trenduri/page.tsx) reads /api/history and falls back first to a localStorage history key that nothing in the repo writes, then to a hardcoded May-2026 snapshot; /trends re-exports the same page (ui/src/app/trends/page.tsx:1-5) and both layouts set canonical /trenduri. EmailCapturePopup (ui/src/components/EmailCapturePopup.tsx) is a lead-capture modal used by the search page that POSTs to /api/leads, stores dismissal flags in localStorage and fires gtag events. Legal pages (/termeni, /confidentialitate) are static Romanian text dated 25 May 2026 with no controller identity or contact channel. A sizeable amount of code is dead: TrendsClient.tsx, SearchBar.tsx, sections/Platforms|StatsBar|Testimonials|FAQ.tsx, ui/button|checkbox|input|label|creative-pricing.tsx, lib/utils.ts, MascotNewspaper/MascotTallHat, the next-themes dependency, and several unreferenced multi-megabyte images in ui/public. Test coverage of this area is limited to four pure functions in auth-flow.mjs (src/auth-ui.test.js); no component or page has tests.

## Notable design decisions

- Fully static export served by the Worker; no server components read user state. All auth and account data flows are client-side with supabase-js (persistSession, autoRefreshToken, detectSessionInUrl) — ui/next.config.ts:9-10, ui/src/lib/supabase-browser.ts:11-17.
- Passwordless-only auth: /signup and /reset are the same SignInOptions component with different labels; signInWithOtp uses shouldCreateUser: true so login and signup are one flow (ui/src/app/signup/page.tsx:7, ui/src/app/reset/page.tsx:7, GoogleSignIn.tsx:103-106).
- Open-redirect protection is centralized in getSafeNextPath (ui/src/lib/auth-flow.mjs:30-33) and the file is .mjs specifically so the Node test runner can import it without a TS toolchain (src/auth-ui.test.js:3).
- /confirm supports both token_hash+type (email OTP, whitelisted types) and PKCE code exchange, and uses a ref-held promise so React effect replay cannot consume a one-time code twice (ui/src/app/confirm/page.tsx:29-31,41-55).
- Premium entitlement in the UI is inferred from GET /api/alerts (403 + code premium_required ⇒ Free, ok ⇒ Premium) rather than a dedicated entitlement endpoint — AccountDashboard.tsx:152-181, AccountNavLink.tsx:26-27.
- Favorites, activity history and an alerts cache are stored only in browser localStorage keyed by user id; nothing syncs them to Supabase (ui/src/lib/account-data.ts).
- The 99 RON price is a single shared constant with an explicit comment that billing must use a server-owned Stripe Price (ui/src/lib/pricing.ts:1-3); no checkout code exists.
- Two pricing surfaces coexist: a landing section (/#pricing, Premium greyed 'Blocat') and a full /pricing page (Premium 'În curând' + test CTA + registry-backed SourceCatalog) — Navbar/Footer link to the section, only the search page and account dashboard link to /pricing.
- Trends page uses a three-tier data strategy: server /api/history → localStorage history (never written) → hardcoded fallback snapshot; /trends is kept as an alias with canonical /trenduri (ui/src/app/trends/page.tsx, trends/layout.tsx:8).
- Google Analytics is mounted unconditionally with a baked-in default ID; RouteTracker sends page_path including the query string on client navigations (layout.tsx:60,140; GoogleAnalytics.tsx:25-30).
- Health page is intentionally manual (runs only on button click), labels cache hits, and its copy states it does not cover Premium/auth/payments/alerts (ui/src/app/health/page.tsx:61-62,76).
- Root metadata defines a site-wide canonical '/' and robots index:true that child routes inherit unless they export their own alternates (ui/src/app/layout.tsx:80-82,107-110).
- Design system is inline: each component redefines its own INK/PINK/BG hex constants and inline styles rather than using the Tailwind @theme tokens declared in globals.css:3-29 (e.g. Hero.tsx:6-9, Footer.tsx:4-7, FeatureCards.tsx:7-9, Pricing.tsx:6-9).
- Dev-only Next rewrite proxies /api to the Node server so the static UI can be developed against src/server.js without CORS (ui/next.config.ts:19-30).
