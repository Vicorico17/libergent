# P0 progress — 2026-09-15

## Implemented

- Normalize spaced GB/TB capacities consistently in marketplace filtering and final classification. Added end-to-end filtering/aggregation regressions.
- Prefer explicit phone model, storage and variant evidence in the title over comparisons in the description. Recognize Samsung models without the optional Galaxy word and distinguish iPhone e models.
- Split Google and email loading states, prevent duplicate submissions, validate email, add a 60-second resend cooldown, and show recoverable Romanian errors. Callback handles query/hash errors, catches network failures, preserves the intended destination on retry, and reuses one-time code exchanges during effect replay. Reject control-character redirect destinations.
- Preserve provider delivery states in private conversation history. Unknown historical delivery stays unknown; a successful bridge response without a delivery receipt is queued. Nested provider failures no longer become success. Seller replies with listing metadata stay attached to that listing.
- Show delivery states, disable duplicate sends while pending/accepted, remove technical contact diagnostics, and provide a marketplace contact link even after lookup/send failure.
- Validate each registered source using two category-appropriate direct queries, count offers after final classification, and record raw/accepted counts, latency and errors. Corrected the previous vehicle-versus-parts query selection.
- Add dated local and production evidence to the source catalog. Demote Anuntul, Price.ro and ShopMania to experimental; preserve attempts and errors in search reports. OLX and Okazii stay active because production returned offers. Registry: 117 adapters, 12 Free / 105 Premium; integration status: 9 active / 108 experimental.

## Validation and limits

- Backend/CLI: 172 tests passed, including auth recovery, redirect validation, source audit, matching and messaging regressions.
- UI lint, TypeScript and the production static build passed. The first sandboxed build could not download Google Fonts; the same build passed with network access.
- Read-only production checks were against the existing deployed revision, before these code changes. They verify HTTP/API behavior, not browser layout or authenticated acceptance.
- No manual deployment, seller messages, calls, login emails, account changes or database migrations were performed. Pushing to main can trigger the repository deployment workflow.
- Local direct probes ran from Node with one page and at most 20 preliminary offers per query. Two queries are a bounded smoke test, not exhaustive coverage. A nonzero count is not manual verification of condition, price, stock or savings.
- No paid browser providers were used. Direct transport failures can depend on runtime/IP; local failures are not proof of production outages. Production checks use the Free API and explicitly record cache state.
